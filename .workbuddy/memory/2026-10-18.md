## 修复 v1.9.3 编译失败（Bug 修复）
- 现象：`:app:compileReleaseJavaWithJavac` 报 "找不到符号 WALLPAPER_URL / WALLPAPER_HISTORY / POSTER_SIZE（位置: 类 HawkConfig）"。
- 根因：上一次提交 ab1b209 往 `BackupManager.BACKUP_KEYS` 里加了三个 Hawk key，但 `HawkConfig` 中从未定义；本项目（竖屏版）没有壁纸/海报尺寸功能（仅有 ApiConfig.wallpaper 字段，来源于源配置 JSON，非设置项），这些 key 疑似从其它 TVBox 分支误拷入。
- 处理：从 `BackupManager.BACKUP_KEYS` 中删除 `HawkConfig.WALLPAPER_URL / WALLPAPER_HISTORY / POSTER_SIZE` 三行（保留 HISTORY_SEARCH、LANDSCAPE_CARD 等真实存在的 key）。
- 版本号按 SemVer 升：versionCode 83→84，versionName 1.9.3→1.9.4（app/build.gradle）。
- 验证：`./gradlew :app:compileReleaseJavaWithJavac` 通过（仅剩 deprecation/unchecked 警告）。

## 经验
- 往 BACKUP_KEYS 加 key 前必须确认 `HawkConfig` 中已定义同名常量，否则直接编译失败；备份 key 列表应与实际设置项一一对应。

## 修复：局域网同步后本地导入的订阅源不可用（"暂无可用数据源"）v1.9.5
- 现象：发送端"本地导入"的订阅，同步到接收端后不可用。
- 根因（两层）：
  1. 旧版本地导入把订阅存到 `Android/data/<pkg>/files/subscriptions/` 并以 `clan://localhost/...` 引用；该地址经 `ApiConfig.clanToAddress` 变成 `http://127.0.0.1:9978/file/...`，由 RemoteServer 从**本机外存**取文件。接收端没有同名文件 → 500/404 → 配置解析失败 → 首页"暂无可用数据源"。
  2. `BackupManager.isLocalUrl()` 只认 `file://` / `content://`，clan:// 被当成网络地址，文件内容没打包进 `localFiles`，只传了 URL 字符串。
- 处理（参考上游项目 `D:\WorkBuddy\TVBoxOS-Mobile` 的做法）：
  1. 新增 `util/LocalImport.kt`：SAF 选中文件后复制到 `filesDir/<subDir>/` 并以 `file://` 引用（私有目录、无需权限、重启不失效）。`SubscriptionActivity.handlePickedFile` 改用它；`addSubscription` 放行 `clan:// / content:// / file://`。
  2. `ApiConfig.loadConfig` 新增本地分支：`assets://` / `content://` / `file://` 直接读文件解析并写缓存（新增 readAssetConfig / readContentConfig / writeConfigCache，缓存写入统一走 writeConfigCache）。
  3. `BackupManager.isLocalUrl()` 增加 `clan://localhost/`（clan://ip/ 属网络地址不算）；`readLocalBytes` 用 `clanToFile()`（外存根路径 → 兜底 getExternalFilesDir → 兜底内置 HTTP /file/）读取内容；`restoreLocalFile` 统一重建为 `filesDir/<subDir>/<md5>.json` 并返回 `file://`。
- 版本：versionCode 84→85，versionName 1.9.4→1.9.5。
- 验证：`./gradlew :app:compileReleaseJavaWithJavac` BUILD SUCCESSFUL（仅 Kotlin deprecation 等警告）。
- 要点：本地文件型配置（订阅源/影视源/直播源）跨设备同步必须"文件内容 + URL"一起传，且接收端要重写为本机可读的 file:// 私有路径；只传 URL 必然失效。
