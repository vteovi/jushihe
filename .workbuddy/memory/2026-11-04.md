## 首页崩溃修复：adjustSort 里 SourceBean 为 null（v1.11.3）
- 崩溃栈：`DefaultConfig.adjustSort` 第 32 行 `sb.getCategories()` NPE，由 HomeFragment 的 sortResult 观察者触发。
- 根因：切换订阅源后 `ApiConfig.loadConfig()` 会先 clear sourceBeanList 再重建，存在空窗；此时 Hawk 里记录的 `HOME_API` 指向的 key 在新列表里查不到，`getSource()` 返回 null，旧代码直接取 categories。
- 修复：
  - `DefaultConfig.adjustSort`：`sb` 为 null 或 `categories` 为 null 时退化为「全部分栏」，不再 NPE。
  - `ApiConfig` 新增 `getSourceName(key)`：源不存在时返回空串。
  - 把 `getSource(...).getName()` 的链式调用全部换成 `getSourceName(...)`：DetailActivity、CollectAdapter、HistoryAdapter、QuickSearchAdapter、SearchAdapter。
  - `SourceViewModel` 的 getDetail / getSearch / getQuickSearch / getPlay 补 `sourceBean == null` 保护（postValue(null) 后返回），与已有 getSort 的保护一致。
- 未动 `PlayFragment.setData`（sourceKey 失效时播放页会白屏），暂不扩大到播放流程。
- versionCode 95 → 96，versionName 1.11.2 → 1.11.3。产物 `APK/MBox_v1.11.3_release_20261104.apk`。

## 首页推荐海报点击进错页面（v1.11.6）
- 现象：添加本地 JSON 订阅后切回在线源，点首页推荐海报本应进搜索页，实际进详情页且空白。
- 原因（两重）：`UserFragment` 的推荐点击只判断 `vod.id` 是否为空，没判断 `msearch:` 前缀（在线源推荐常是搜索词条，`id="msearch:片名"`，无真实详情）；
  另外切换订阅后首页可能残留上一份配置的推荐数据（同 site key 的订阅会命中同一份 `sort_cache_<key>_rec`），其 sourceKey 在当前配置里不存在，进详情只会拉空。
  `GridFragment` 早就有 `msearch:` 判断，`UserFragment` 漏了。
- 修复：`UserFragment` 点击推荐时 `isSearchEntry = id 为空 || id 以 msearch: 开头 || ApiConfig.get().getSource(sourceKey) == null`，
  命中就带 title 跳 `FastSearchActivity`，否则进 `DetailActivity`；两种分支都先 put title。
- versionCode 98 → 99，versionName 1.11.5 → 1.11.6。产物 `APK/MBox_v1.11.6_release_20261104.apk`。

## 平板侧栏顶部横线 + 收藏/历史列数自适应（v1.12.1）
- 侧栏横线根因：`layout-sw600dp/activity_main.xml` 里用外层白色 FrameLayout + `NavigationRailView.layout_marginTop=24dp` 下移 rail，
  rail 自身 Material 背景/阴影的**上边缘**在 24dp 处露出一条水平分界线。
- 改法：去掉外层 FrameLayout，rail 直接作为 LinearLayout 首子 View 铺满 `match_parent`（背景/阴影一直延伸到状态栏底下），
  改用 `android:paddingTop="32dp"` 兜底 + `MainActivity.applyNavRailStatusBarPadding()` 用 `WindowInsetsCompat.Type.statusBars()` 的
  真实 inset 重算 `paddingTop = max(32dp, insetTop + 8dp)`；`onConfigurationChanged` 里 `requestApplyInsets` 重取。
  手机布局没有 `nav_rail` id，findViewById 返回 null 直接跳过。
  - 验证过 Material 1.4.0 `NavigationRailView.onLayout`：menuView 是 FrameLayout 子 View，paddingTop 会把它下移，随后 rail 再加默认 topMargin，不影响。
- 收藏/历史页原来写死 `GridLayoutManager(this, 3)`，横版 16:9 卡片在 360dp 手机竖屏只有 ~113dp 宽、文字压满，看不清。
  改为 `Utils.getPosterSpanCount(this)`（横版屏宽/400dp 四舍五入，手机竖屏 = 1 列整宽；竖版屏宽/180dp，至少 2 列、最多 6 列），
  并补 `onConfigurationChanged` 更新 spanCount（清单有 configChanges 不重建）。与首页/搜索页列数算法保持一致。
- versionCode 100 → 101，versionName 1.12.0 → 1.12.1。产物 `APK/MBox_v1.12.1_release_20261104.apk`。

## 横竖屏切换后分栏列数不实时更新（v1.12.2）
- 现象：旋转屏幕后首页分栏里的卡片列数不变，必须滑到别的分类再切回来才更新。
- 原因：列数只在 `GridFragment.onFragmentResume()` / `UserFragment.onFragmentResume()` 里重算，而清单声明了 `configChanges(orientation|screenSize)`，
  旋转不重建页面、也不触发分栏切换（onFragmentResume），所以没有重算时机。
- 解决：
  - 两个 Fragment 都新增 `onConfigurationChanged()`，直接调用抽出来的 `applySpanCount()` / `applyHotSpanCount()`。
    已验证 androidx.fragment 1.3.6 的 `FragmentActivity.onConfigurationChanged` 会 dispatch，`Fragment.performConfigurationChanged` 会继续分发给 childFragmentManager，
    所以 HomeFragment 下的所有分页 Fragment 都能收到（分页用 `FragmentStatePagerAdapter(getChildFragmentManager())`）。
  - 列数变化时不重建 LayoutManager，改 `setSpanCount()`，保留滚动位置；`GridFragment` 的 `changeView()` 会新建一个 RecyclerView（lm 为 null），
    所以提前返回条件必须同时判断 `lm instanceof V7GridLayoutManager && getSpanCount()==span`，否则新页面会没有 LayoutManager。
  - `UserFragment` 原来每次 onFragmentResume 都 new 一个 GridLayoutManager（会重置滚动），顺带改成只在列数变化时更新。
- 至此所有 `Utils.getPosterSpanCount()` 调用点（首页分栏/主页推荐/搜索/收藏/历史）都已覆盖 onConfigurationChanged。
- versionCode 101 → 102，versionName 1.12.1 → 1.12.2。产物 `APK/MBox_v1.12.2_release_20261104.apk`。
