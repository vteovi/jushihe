## 构建环境异常（重要）
- 本次会话机器上 **`C:/Java/jdk-17` 与 `C:/Android/Sdk` 都不存在**（`Build-MBox.ps1` 里写的就是这两个路径），`java` 不在 PATH，
  `~/.gradle` 也没有缓存。`./gradlew` 直接报 `JAVA_HOME is not set`。
- 因此本轮**只改了代码、没有编译、没有出 APK**。下次要构建前先确认 JDK17 + Android SDK 是否恢复，或重新指定 `JAVA_HOME`/`sdk.dir`。

## GitHub Actions 云端构建（解决本机无 JDK/SDK）
- 本机 JDK/SDK 缺失，改用 GitHub Actions 出包，已打通并成功产出 `MBox_v1.14.0_release_20261108.apk`（41MB）。
- `.github/workflows/build.yml`：push 到 `master`/`dev`、推 `v*` tag、或手动 workflow_dispatch 触发；
  JDK 17 装 Android SDK → 切 JDK 11 跑 `./gradlew assembleRelease` → 上传 artifact（保留 30 天）→ tag 时自动挂 Release。
- 签名：本地 `TVBoxOSC.jks` 用 base64 存进仓库 Secret `KEYSTORE_BASE64`，CI 解码回根目录再用，**产物签名与本地一致，可覆盖安装**。
  仓库是 public，jks 不能入库（`.gitignore` 已忽略 `*.jks`）。未配置 Secret 时 CI 会 keytool 临时生成（签名不同，需卸载重装）。
- `app/build.gradle` 的 `storeFile` 改成 `rootProject.file('TVBoxOSC.jks')`：原来 `file('..\\TVBoxOSC.jks')` 的反斜杠在 Linux 上不是路径分隔符，CI 必失败。
- 新增 `.gitattributes` 固定 `gradlew`/`*.yml` 为 LF，防 Windows 编辑后 CI 上 `bad interpreter`。
- 踩坑记录（改 workflow 时注意）：
  1. `tags:` 必须写在 `on.push` 下面，写成与 `push` 同级会 `Invalid workflow file`，run 直接 0 job 秒失败。
  2. 新版 cmdline-tools 的 `sdkmanager` 要求 **JDK 17+**，所以先用 JDK 17 装 SDK，再 setup-java 11 给 Gradle。
  3. `android-actions/setup-android` 的 `packages: 'tools ...'` 已失效（`tools` 包下架），改为 `platform-tools platforms;android-33 build-tools;33.0.2`。
  4. 首次构建约 5 分钟（Gradle 发行版 + 依赖 + 编译），后续有缓存更快。
- 分支：CI 提交同时 cherry-pick 到 `master` 和 `dev`（默认分支要有 workflow，网页上才有 Run workflow 按钮）。
