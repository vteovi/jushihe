## GitHub Actions 云端构建（解决本机无 JDK/SDK）
- 本机 JDK/SDK 缺失，改用 GitHub Actions 出包，已打通并成功产出 `MBox_v1.14.0_release_20261108.apk`（41MB）。
- `.github/workflows/build.yml`：push 到 `master`/`dev`、推 `v*` tag、或手动 workflow_dispatch 触发；
  JDK 17 装 Android SDK → 切 JDK 11 跑 `./gradlew assembleRelease` → 上传 artifact（保留 30 天）→ tag 时自动挂 Release。
- 签名：本地 `TVBoxOSC.jks` 用 base64 存进仓库 Secret `KEYSTORE_BASE64`，CI 解码回根目录再用，**产物签名与本地一致，可覆盖安装**。
  仓库是 public，jks 不能入库（`.gitignore` 已忽略 `*.jks`）。未配置 Secret 时 CI 会 keytool 临时生成（签名不同，需卸载重装）。
- `app/build.gradle` 的 `storeFile` 改成 `rootProject.file('TVBoxOSC.jks')`：原来 `file('..\\TVBoxOSC.jks')` 的反斜杠在 Linux 上不是路径分隔符，CI 必失败。
- 新增 `.gitattributes` 固定 `gradlew`/`*.yml` 为 LF，防 Windows 编辑后 CI 上 `bad interpreter`。
- 踩坑记录（改 workflow 时注意）：
  1. `tags:` 必须写在 `on.push` 下面，写成与 `push` 同级会 `Invalid workflow file`，run 直接 0 job 秒失败。
  2. 新版 cmdline-tools 的 `sdkmanager` 要求 **JDK 17+**，所以先用 JDK 17 装 SDK，再 setup-java 11 给 Gradle。
  3. `android-actions/setup-android` 的 `packages: 'tools ...'` 已失效（`tools` 包下架），改为 `platform-tools platforms;android-33 build-tools;33.0.2`。
  4. 首次构建约 5 分钟（Gradle 发行版 + 依赖 + 编译），后续有缓存更快。
- 分支：CI 提交同时 cherry-pick 到 `master` 和 `dev`（默认分支要有 workflow，网页上才有 Run workflow 按钮）。

## 内置默认订阅源（v1.15.0）
- 位置：`res/values/strings.xml` 的 `string-array name="api"`（原来是空的 `<item />`，上游刻意留空）。
  新增 `api_names` 数组做中文名展示，两个数组**必须同序等长**；`App.putDefaultApi()` 按下标配对。
- 内置 5 个源：龙门影视 `http://box.iqinu.com`、饭太硬 `http://www.饭太硬.cc/tv`、
  饭太硬备用 `http://www.饭太硬.com/tv/`、巧技 `http://cdn.qiaoji8.com/tvbox.json`、讴歌 `http://tv.nxog.top/m/`。
- 源可用性实测（2026-11-08）：`http://box.iqinu.com` **可用**，返回 `2423...` 开头的 hex 串，
  正好命中 `ApiConfig.FindResult` 里 `content.startsWith("2423")` 的加密配置分支（key `$#123456#$`）；
  注意它的 **https 版本是宝塔默认页（无效），必须用 http**。其它域名本机网络下 DNS/超时未验证，不代表失效。
- 老用户升级补齐：`HawkConfig.DEFAULT_SUBS_VERSION` 存一个 int 版本号（`App.BUILTIN_SUBS_VERSION`），
  只补一次新增默认源（按 URL 去重），补完写版本号；用户手动删掉的源不会每次启动又冒出来。
  **以后往 api 数组里加源，记得把 BUILTIN_SUBS_VERSION +1**，否则老用户升上来看不到新源。
- 备份还原：`BackupManager.BACKUP_KEYS` 里加上 `DEFAULT_SUBS_VERSION`，避免还原后又被补一遍默认源。
- 首次安装时第一个源默认选中并写入 `API_URL`；若老用户一个源都没选中（API_URL 为空），补齐后自动选第一个。

## 直播页闪退修复（v1.16.2）
- 崩溃栈：`LiveActivity.getFirstNoPasswordChannelGroup` 里 `getGroupPassword().isEmpty()` NPE。
- **根因**：v1.15.1 我在 `ApiConfig` 里手工 new 的那个「本地 proxy 直播源占位组」只 `setGroupName`，
  `groupPassword` 是 null。从「换直播源」走 `reloadLiveConfig()` 时直接 `initLiveState()`
  → 第一个组就是它 → 必崩。教训：**手工构造 LiveChannelGroup 必须把 groupIndex/groupPassword 一起填**。
- 双保险：`LiveChannelGroup.getGroupPassword()` 统一 null→"" 兜底（所有调用点一次性安全）。
- `reloadLiveConfig` 原来绕过 `initLiveChannelList` 直接 initLiveState，遇到占位组既没频道又会崩；
  现在抽出 `isProxyOnlyGroupList()` 两处共用，proxy 组统一走 `loadProxyLives`。
- `initLiveState` 加空列表兜底进「暂无直播频道」；`parseProxyLiveContent` 包 try/catch，解析失败提示并进空状态。
- `.gitignore` 加 `/dist/`（本地下载的 CI 产物不再进仓库）。
