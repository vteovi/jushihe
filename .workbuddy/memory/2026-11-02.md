# 2026-11-02

## 新增：大屏平板横屏适配（v1.10.0）

### 背景问题
- 全部 Activity 在清单里锁死 `screenOrientation="portrait"`，平板横屏拿起来仍被强制竖屏，左右大黑边。
- autosize 设计稿 `design_width_in_dp=360`（竖屏手机），`BaseActivity.getSizeInDp()` 恒返回 360，平板横屏 1280dp 宽时所有 dp 尺寸被放大 3.5 倍，界面巨大。
- 没有任何 `layout-sw600dp` 变体，也没有在 `onConfigurationChanged` 里重算 autosize。

### 方案（对齐可用版 TVBoxOS-Mobile 的平板做法）
1. **AndroidManifest**：删掉各 Activity 的 `android:screenOrientation="portrait"`；`<application>` 加 `android:resizeableActivity="true"`。`LocalPlayActivity` 的 landscape 保留。
2. **BaseActivity**
   - 新增 `applyScreenOrientation()`（在 `super.onCreate` 之前调用）：手机 `sw<600dp` 锁竖屏，平板 `SCREEN_ORIENTATION_FULL_SENSOR`。
   - 新增钩子 `lockPortraitOnPhone()`，默认 true；`LiveActivity`、`DetailActivity`、`LocalPlayActivity` 覆盖为 false（播放类不能被硬锁竖屏，否则会覆盖 LocalPlay 的 landscape）。
   - `getSizeInDp()`：`smallestScreenWidthDp >= 600` 时返回 `screenWidthDp`（原生 dp、缩放比 1:1），否则仍是 360。
   - 新增 `onConfigurationChanged()` → `AutoSize.autoConvertDensity(this, getSizeInDp(), isBaseOnWidth())`（清单声明了 `configChanges`，横竖切换不重建 Activity，必须手动重算）。
3. **Utils**
   - 新增 `isTablet(Context)`：`smallestScreenWidthDp >= 600`。
   - `getPosterSpanCount()` 按屏宽动态算：竖版 2:3 海报目标列宽 180dp（2~6 列）、横版卡片 400dp（1~4 列）。手机 360dp 时结果仍是 2 列 / 1 列，与原固定值一致。
4. **竖屏/平板两套主界面**
   - 新增 `layout-sw600dp/activity_main.xml`：左侧 `NavigationRailView`(id=`nav_rail`, 88dp) + 右侧 ViewPager。
   - `MainActivity.kt` 改为 `findViewById` 取 `NavigationBarView`（先找 `bottom_nav`，再找 `nav_rail`），不再用 `mBinding.bottomNav`。
5. **大屏内容**
   - `layout-sw600dp/activity_detail.xml`：播放器区域 250dp → 400dp，`llLayout` 改 `match_parent` + 内容 ScrollView `0dp/weight=1`。
   - `layout-sw600dp/fragment_grid.xml`：RecyclerView 左右内边距 10dp → 24dp。
6. **播放器方向**：`PlayFragment.changedLandscape(false)` 与 `PlayerTitleView` 返回键，平板下改为 `FULL_SENSOR`，不再强制 `PORTRAIT`。
7. 版本：`versionCode 90→91`，`versionName 1.9.10→1.10.0`（feat 升 MINOR）。

### 踩过的坑（重要）
- **`<include>` 的 id 不能与子布局根的 id 重复**，否则 data binding 直接报 `<include id='@+id/xxx'> conflicts with an ID used by a view in this layout`。
- **同一 id 在 `layout/` 和 `layout-sw600dp/` 里类型不同**（`BottomNavigationView` vs `NavigationRailView`）会被 ViewBinding 判为冲突。解决办法：平板用**不同 id**（`nav_rail`）+ `findViewById` 取共同基类 `NavigationBarView`。
- **详情页播放器 `previewPlayer` 是根 `FrameLayout` 下的独立 `FragmentContainerView`，不在 `previewPlayerPlace` 里**。所以不能简单把 `llLayout` 改成 horizontal 做左右分栏——`toggleFullPreview()` 用 `setLayoutParams(FrameLayout.LayoutParams(MATCH_PARENT, MATCH_PARENT))` 只能在它自己的父容器里放大，分栏后全屏会有 3/5 限制。最终选择"加高播放器 + 内容下滚"的稳妥方案。

## 微调：侧边导航栏图标下移（v1.10.1）
- 现象：平板 `NavigationRailView` 第一个图标（首页）几乎贴到顶部状态栏。
- 做法：`layout-sw600dp/activity_main.xml` 外面包一层 88dp 宽、白底的 `FrameLayout`，rail 自身 `layout_height=match_parent` + `layout_marginTop=28dp`。
  - 不直接把背景留在 rail 上，是为了避免下移后顶部露出父容器底色形成色块。
  - 不用 `app:menuGravity="center"`：4~5 个 item 在 800dp 高的平板上居中会整体跑到屏幕中间，位移过大。
- 版本：`versionCode 91→92`，`versionName 1.10.0→1.10.1`（fix 升 PATCH）。
- 产物：`APK/MBox_v1.10.1_release_20261102.apk`。
