## 修复：同步/还原后首页源不对，必须"进订阅管理页再退出"才生效（v1.9.6）
- 现象：局域网设备同步（或备份还原）结束后，订阅列表看得到，但首页数据源还是接收端旧的；只有进一次"订阅管理"再退出才生效。
- 根因：`BackupManager` 用 `getSharedPreferences("Hawk")` 直接读写设置，而 Hawk 2.0.1 内部默认存储文件名是常量 `STORAGE_TAG_DO_NOT_CHANGE = "Hawk2"`（已解压 `hawk-2.0.1.aar` 用 strings 验证过 `HawkBuilder.class` 里确有 "Hawk2"）。
  → 导出读的是不存在的空文件（读不到任何设置），导入又写进 "Hawk"，Hawk 实际读 "Hawk2"，所以 API_URL / HOME_API 等全部不生效；
  只有走 `Hawk.put` 的订阅列表能生效；用户"进订阅页再退出"生效，是因为 `SubscriptionActivity.onPause` 里 `Hawk.put(HawkConfig.API_URL, mSelectedUrl)` 重新写了一次。
- 处理（与上游 `D:\WorkBuddy\TVBoxOS-Mobile` 2.22.6 提交 3101638 完全一致）：
  - 新增 `HAWK_PREF = "Hawk2"`，导出/导入两处 `getSharedPreferences` 都改用它；
  - 导出：`API_URL / LIVE_URL` 改走 `Hawk.contains` + `Hawk.get` 取真实 url 再判断本地文件并打包内容（sp 里是 "type#value" 包装串，直接判会误判）；其余项原样搬运 Hawk 序列化串（List/Set 也能无损还原）；
  - 导入：`API_URL / LIVE_URL` 用 `restoreLocalFile` 重建后用 `Hawk.put` 写回真实值（走 editor 会绕过 Hawk 序列化）；订阅列表仍走 `Hawk.put`；其余项 `editor.putString(原始串)`；
  - `editor.apply()` → `editor.commit()`（导入后立即 relaunch，异步 apply 可能没落盘就被杀）。
- 版本：versionCode 85→86，versionName 1.9.5→1.9.6。
- 验证：`./gradlew :app:compileReleaseJavaWithJavac` BUILD SUCCESSFUL。

## 修复：在线订阅源（含 DRPY / box.iqinu.com）首页弹"更新订阅失败"（v1.9.7）
- 现象：用在线订阅源（如默认 DRPY `https://box.iqinu.com`）时首页反复弹"更新订阅失败"，且"所有在线源都这样"。
- 实测定位（非猜）：
  - 该源按 UA 分发：`okhttp/3.15` 才返回 67662 字节真配置（项目 UA 正确）；浏览器/无 UA 返回"站点创建成功"占位页。
  - 真配置是 `$#...#$` 包裹的 AES-128-CBC 加密 hex，靠 `ApiConfig.FindResult()` 的 `2423` 分支解密（本项目与 `TVBoxOS_Portrait-main` 的 FindResult 一致，**解密不是问题**）。
  - 解密后顶层 `spider` = `http://test.59bang.com/jar/lm60601.jar;md5;edf2bad2a6943342039f03ade94904dd`；该 jar md5 与配置一致、dex 内含 `com.github.catvod.spider.Init` 类 —— **源和 jar 本身都没问题**。
  - 弹窗只来自 `loadJar` 的 error 分支（HomeFragment.kt:257），即 spider jar 加载失败。
- 真正根因（对比可用版 `D:\WorkBuddy\TVBoxOS-Mobile`）：
  1. 旧 `JarLoader.loadClassLoader` 必须等 `Init.init()` **成功**才算成功；但 `Init.init()` 里常做非致命操作（典型是 GoProxy 等原生库运行时下载失败），一旦失败就把整份订阅判死 → 类加载器不注册 → 所有 type:3 爬虫源取不到 → 弹"更新订阅失败"。
  2. **更关键**：本项目 `targetSdkVersion 34`（Android 14）。Android 14 起禁止 `DexClassLoader` 从可写目录加载 dex，旧写法 `new DexClassLoader(csp.jar, ...)`（csp.jar 未设只读）在 Android 14 设备上**直接加载失败** → `jarLoader.load()` 返回 false → 弹窗。这正好解释"之前能用现在不行 / 所有在线源都这样"。
- 处理（对齐 Mobile 可用版）：
  - 整体替换 `catvod/crawler/JarLoader.java`：`Init` 类能从 dex 加载出来即视为订阅可用（不再要求 `Init.init()` 成功）；新增 `createClassLoader()`——API≥34 用 `InMemoryDexClassLoader` + 新增的 `JarResourceClassLoader`(parent 补 jar 内资源)，<34 用传统 `DexClassLoader` 并对 jar 调 `setReadOnly()`。
  - 新增 `catvod/crawler/JarResourceClassLoader.java`（Mobile 有、本项目缺）。
  - `JsLoader.java` 同样改用 `JarLoader.createClassLoader`（修 JS 爬虫在 Android 14 的同类问题）。
- 版本：versionCode 86→87，versionName 1.9.6→1.9.7。
- 验证：`./gradlew :app:compileReleaseJavaWithJavac` BUILD SUCCESSFUL。
- 注意：若某源的 `Init` 类本身从 dex 都加载不出来（加密/损坏），仍会判失败，那是源自己的问题，与本项目无关。

## 修复：直播页崩溃（LiveActivity NPE，Build 1.9.7 / Android 16）
- 崩溃栈：`LiveActivity.initLiveState(LiveActivity.java:907)` → `liveChannelGroup.getLiveChannels().iterator()` 对 null 调用 → NPE。设备小米 Android 16 (SDK 36)。
- 根因：`ApiConfig.parseJson` 直播解析里有一段标注 `(WIP)` 的遗留代码（原 `// takagen99: Load Live Channel from settings URL (WIP)`），在 `infoJson` 含 `lives` 时**无条件**执行：创建一个只设了 groupName（代理 URL）的 `LiveChannelGroup` 并 add 进 `liveChannelGroupList`，但**从未 `setLiveChannels`**（字段为 null）。
  - 常规结构化 `lives` 源虽走 `loadLives` 正确填充，但末尾仍被追加这个空 group；遍历到它就 NPE。所以进直播页几乎必崩。
  - 上游 `TVBoxOS-Mobile` 也有这段，但它外面包了 `if (!StringUtils.isBlank(liveURL_final))`——只要有配置直播源就不会为空，因此同样会加空 group（上游该路径一样有隐患，只是用户没触发）。
- 处理：
  1. 删除该 WIP 块（根因）：它只塞了一个无频道的 group，对正常源是多余、对 proxy/txt 类源（不走 loadLives）则导致列表仅有此空 group 进而崩溃。删除后结构化源列表干净；proxy/FongMi-0 类不支持的源列表为空 → 走 `showChangeLiveSourceDialog()` 优雅降级而非崩溃。
  2. 双保险：`LiveChannelGroup.getLiveChannels()` 加 null 兜底，返回空 `ArrayList`，防止任何其它路径创建的 group 再触发同类 NPE（同时护住 `getLiveChannels(int)`、`setNewData` 等消费点）。
- 版本：versionCode 87→88，versionName 1.9.7→1.9.8。
- 验证：`./gradlew :app:compileReleaseJavaWithJavac` → BUILD SUCCESSFUL（仅 Kotlin runtime JAR 版本警告，无错误）。
